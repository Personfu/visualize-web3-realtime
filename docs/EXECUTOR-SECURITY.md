# Private executor access

The executor can forward real agent actions when `SPERAXOS_API_KEY` is configured. Previously its HTTP task/agent controls and WebSocket snapshots had no inbound credential check. The default keyless upstream adapter is a synthetic simulation; that does not establish that any deployed instance was exposed.

The executor now requires `EXECUTOR_ACCESS_TOKEN` before creating its upstream client or SQLite store. Generate a random base64url token with at least 32 characters, keep it server-side, and send it as a Bearer header for control requests. Missing, malformed, conflicting and duplicated credentials fail closed. JSON is bounded to 1 MiB. Responses, including denials, use private/no-store caching and generic error text.

The default bind address is 127.0.0.1. Remote operation needs a reviewed TLS proxy and network policy. Set `EXECUTOR_ALLOWED_ORIGINS` to exact HTTPS browser origins, or an HTTP loopback origin for development. There is no wildcard. CORS is an additional browser boundary; it does not replace credentials. Do not expose an unconfigured listener to the internet.

`EXECUTOR_VIEWER_TOKEN` is optional, distinct from the control token, and grants private read access only: GET and WebSocket snapshots/events. It cannot enqueue tasks, spawn agents or stop agents. Native clients may use a Bearer header. Browser clients use `web3viz.v1` plus the `web3viz.auth.` credential subprotocol; the server negotiates only the public application protocol. Treat the handshake header as sensitive and redact it in proxies. Credential URLs and redirects are rejected.

Never put either token or `SPERAXOS_API_KEY` into a `NEXT_PUBLIC_` variable, URL, repository, analytics event or persistent browser storage. The browser hook retains the legacy option name `apiKey`, but accepts only a scoped, read-only viewer token supplied in memory by an operator's authenticated session integration. The bundled page no longer imports a privileged upstream key into its client build. Its offline demo needs no credential. A production viewer-session bridge is not implemented or verified by this patch; keep live mode disabled until one is reviewed.

The upstream Node adapter uses Authorization headers, rejects credential-bearing/insecure non-loopback base URLs and does not follow HTTP or WebSocket redirects. Its health report distinguishes mock mode from unverified real upstream connectivity. No live signing, wallet, trade, tool, model or paid API call is a dependency test.

`npm run test:offline` checks the real inbound route/upgrade logic against synthetic services, including 48 anonymous/wrong-credential REST denials, viewer write denial, duplicate headers, conflicting WebSocket credentials, origins, body bounds, caching and redirect rejection. These tests do not prove a real upstream deployment or native SQLite rollout. CI regenerates the tracked executor output and rejects source/output drift; the supported start command remains `tsx src/index.ts`.

Before rollout, prepare private control/viewer credentials and exact origins in the hosting environment, then verify a matching-source deployment, denied anonymous requests and actual running versions. No production configuration, credential revocation, old Git objects or deployed bundle was changed by the source patch.

Browser destinations are an explicit reviewed list in `packages/core/src/transport/index.ts`. Authenticated development currently allows only loopback port 8765; a private production WSS endpoint must be added in source review before connecting. Arbitrary hosts, alternate ports/paths, URL credentials and authenticated use of the legacy public upstream stream are rejected. The legacy upstream is anonymous-only; its real server SDK connection remains separate. A public environment variable cannot expand this list.

`STATE_PATH` must resolve to a simple `.db`, `.sqlite` or `.sqlite3` filename directly inside the working directory's managed `data` folder, or use the explicit in-memory SQLite mode. Traversal, external/nested locations, reserved device names and symlinked database directories/files/sidecars fail closed. The default `./data/executor.db` stays compatible. Existing custom external paths require operator review before rollout; this change never silently relocates a database or reads production contents. Disposable filesystem regressions exercise these rules without opening SQLite.
